## M1 指标 + 形态 + 单级别预警 —— 完成

已实现：
- `indicators/`：SMA/EMA/Wilder/StdDev/RSI/MACD/BOLL/ATR/KDJ 增量指标；
  量能 = 同一批指标作用在 volume 上，不单设"量能指标"。口径见 **ADR-0006**。
- `patterns/`：白名单 AST 表达式引擎（A 档）+ 结构原语（B 档）+ `@pattern` 插件（C 档），
  三档同一张函数表可自由混用；**三值逻辑**贯穿全层（预热期 None ⇒ 不成立）。
- `rules/`：单级别规则模型与 YAML 加载（加载期编译校验）、`RuleEngine`
  （state/event 两种模式、按 bar 时间的冷却与去重、关键值快照、`prime` 预热不发信号）。
- `sinks/notify.py`：Telegram / Bark / 控制台；单渠道失败不影响其他渠道也不打断行情处理。
- `scripts/watch.py`：盯盘入口（WS/轮询 → BarStore → 规则 → 推送）。

**验收**
- [x] **指标增量结果与全量重算逐点一致**。参照实现是**独立写的朴素全量重算**
      （每个位置从头算一遍，O(n²)），不复用增量类 —— 否则就是自己跟自己比。
      9 个指标 × 两个市场的真实行情夹具，相对容差 1e-9 全过。
- [x] **纯逻辑层单测覆盖，无网络无磁盘依赖**。实证：**掐断 socket 出网后
      284 项测试全过**（含 feed 层，靠夹具与假连接）；余下 7 项是 Parquet 落盘，本就要用磁盘。
- [x] **一条单级别规则在实时行情下正确推送，内容含关键值**。
      2026-08-28 13:21–13:33 UTC 用**出厂规则** `volume-spike`（未降阈值）真跑 OKX 实时行情：
      13:28 BTC 与 ETH 各触发一次（vol_ratio 10.26 / 5.67），推送正文含
      触发价、close、volume、vol_ratio、ema20、rsi14、atr14，时间按市场显示为 UTC。
      启动预热 1500 根 1m（派生 481 根高周期）**未产生任何历史信号**，符合预期。
- [x] **两个市场在同一进程、同一条规则下并行**。13:43–13:51 UTC（期货夜盘时段）真跑：
      加密 16 根 + 期货 16 根 bar，触发 2 条信号，**0 根异常 bar**，推送失败 0。
      信号正文含 close/volume/vol_ratio/ema20/ema60/rsi14/atr14/macd_hist/boll_upper，
      期货按北京时间+交易日显示、加密按 UTC 显示。

**真跑中发现并修掉的（都补了回归测试）**
1. `IndicatorCache` 每次求值从头扫整个窗口找未喂样本 —— 结果与 `update` 调用次数全对，
   **按结果或调用次数写的测试都测不出来**，但复杂度 O(窗口长度)，预热 2000 根跑了 5 分半。
   改用 bisect 定位起点。护栏用"是否逐个访问旧样本"的序列包装类，并验证过它在旧实现下确实失败。
2. 预热后未给 Feed 游标播种 —— 期货首轮轮询把 17 根重叠窗口当新数据重发，
   刷出 34 条"时间倒流"。补 `BarStore.resume_map()` + `PollingFeed(resume_from=...)`。
   修复后同样时段重跑：**0 条**。
3. `pin_bar` 判"另一侧影线 ≤ 实体"，会把实体趋近 0 的十字锤判掉；改为影线间的相对比较。
4. `rsi(close)` 少写周期时会把收盘价当周期数（价格恰为整数时连报错都没有）；改为直接拒绝。
5. 三个新子包缺 `__init__.py`，正式打包会漏掉 `indicators`/`rules`/`sinks`。

**已知限制**
- Telegram/Bark 的**实际投递未验证**：`.env` 里三个渠道凭据都为空，本机只跑到控制台渠道。
  格式化与失败隔离有单测，但"手机上真收到"需要你配好凭据后自测。
- 单级别：多级别条件树、window 模式、TTL、状态机持久化都在 M2，加载器会明确拒绝相关写法。
- 盘中预报（tentative）留了字段但未接线，等 M3 的 Web 面板一起做。

## M2 多级别规则引擎【核心里程碑】—— 完成

语义定案见 **ADR-0007**。规则泛化成**有序条件链路**（长度 1 即单级别），
因此 M1 与 M2 **共用一个模型、一个引擎**，M1 的规则一个字都不用改。

已实现：`rules/state.py`（状态机：推进/回退/TTL/冷却）、`rules/engine.py`
（记账与判定分两步、`on_bars` 批入口、`snapshot`/`restore`/`cursor`/`resume`）、
`store/runtime_store.py`（SQLite WAL 持久化）、`feed/replay.py`（ReplayFeed）、
`scripts/replay_check.py`（红线验收工具）；`scripts/watch.py` 已接上持久化与重启补判。

**验收**
- [x] **红线：同一时段 replay 与 live 产出信号逐条一致**。
      2026-08-29 14:12–14:21 UTC 真跑三段式规则（trend 15m/state → setup 5m/window(4)
      → trigger 1m/event，ttl 6 bars，cooldown 10m，去重绑 trend bar）：
      **1216 根 bar（600 根历史 ×2 标的 + 实时 8 分钟）落 Parquet 后回放，16 条信号逐条一致**。
      离线版另有 1000 根 / 92 条信号的对拍，以及 `tests/test_replay.py` 的双标的多级别对拍。
      **根因不是靠对拍碰出来的**：引擎全部时间取自 `bar.close_ts`，一处不读系统时钟 ——
      有专门单测把 `time.time`/`datetime.now` 换成会爆炸的桩，整条链路仍跑通。
- [x] **进程重启后状态机恢复，不丢报不重报**。崩在信号**之前**存盘，新进程恢复后
      `resume` 重放整段历史：游标之前只重建状态、之后补判，落库结果与全程不重启的基准逐条一致；
      另有反证测试（抹掉去重表就会重报）证明挡住重报的确实是持久化的去重表。
- [x] **trend 失效时链路正确回退，无残留 armed 状态**。回退目标是失效条件**之前那一段**
      （趋势还在就别把趋势判断也丢掉）；同一根上"trend 失效且扳机成立"时**必须回退不发信号**。
- [x] **换月当日新旧合约状态互不污染**。状态按 (rule, symbol) 分实例，去重键含 symbol；
      快照也按合约分行。新合约从 IDLE 起，不继承旧合约进度。

**已知限制**
- 跨标的的信号先后不是确定量（各标的状态独立），比对 replay/live 须**按标的分组后再比**。
- 重启时**新增**的规则，在游标之前的历史不会被记账，要等积够新 bar 才可能触发。
  刻意的保守取舍 —— 总比一上线就按旧数据补报一堆信号好。
- 盘中预报（tentative）仍只有字段、未接线，随 M3 的 Web 面板一起做。
- 长时间连续运行（24h+）与真实换月当日的行为尚未观察，建议随 M3 一起跑。

## M4 策略层 + 纸上撮合 —— 代码与离线验收完成，待长跑

撮合与风控口径定案见 **ADR-0010**。核心约束：**撮合口径与 ADR-0008 的统计口径共用同一套代码**，
否则"统计说赚钱、模拟盘说不赚"无从排查。

已实现：`trade/`（model / strategy 定量 / risk 风控闸 / paper 撮合 / desk 交易台 / loader 配置）、
`config/trading.yaml`（**默认 enabled: false**）、`scripts/paper_run.py`（纸上回测）、
面板新增「纸上账户」页；运行态与成交流水落 SQLite。487 项单测、ruff、mypy strict 全绿。

**验收**
- [x] **每条风控规则有针对性单测（触发即拒单）**。`test_reject_*` 系列一条规则一条测试，
      且每条**只**违反那一条、其余保持宽松，确保拒单原因不会张冠李戴：
      重复信号 / 不足一手 / 权益不足 / 单笔风险 / 单笔名义 / 单品种 / 总持仓 / 日亏熔断 / 频率。
      另有反证测试（不恢复去重表就会重复下单）与"被拒的单不占频率额度"。
- [x] **成交记录与信号一一对应**。真实行情实测（2594 根 1m、两个标的）：
      **44 条信号 → 44 笔开仓 → 44 笔平仓**，每笔开仓都指向真实信号、无重复、开仓↔平仓一一对应。
      落库后再核对一遍同样成立。
- [x] 附带：撮合与统计的出场判定**逐字段相等**（把滑点费用归零后对拍出场原因/价格/时刻）。
- [ ] **模拟盘连续运行一周无异常** —— 这条只能靠时间，留给长跑。

**真跑逼出来的设计修正（写进 ADR-0010）**
- 定量层原本不知道风控上限，44 条信号被 `per_trade_notional` 全拒；只传单笔上限后
  又被更紧的单品种上限全拒。改成**三个硬上限取最紧者，定量时就截断** ——
  风控闸回归兜底角色，它响就意味着异常。
- 开仓那一根原本不判出场，与统计口径差了一根。以开盘价入场后这根 bar 真的走过了它的
  高低区间，触及止损是真实发生的，不是偷看。

**已知限制**
- 纸上撮合**没有盘口、不看深度、bar 内路径不可见**，不要拿它当实盘预期（ADR-0010 已列全）。
- 一个标的同时只持一笔仓位；加仓/对锁不做（做了"一一对应"就失去意义）。
- 首次真跑的结论是**负的**：ATR×1.5 的止损在 1m 上只有 ~0.1%，36/44 直接被止损打掉，
  手续费吃掉近一半亏损。这是口径问题不是代码问题 —— 正是统计页那张「价格走到了哪里」要说的事。

## 表达式与周期能力（2026-08-31 补，ADR-0011）
对照用户真实打法（看大做小：大级别定方向 -> 回踩小时/日线均线 -> 分钟双底或 5m 金叉后箱体）
逐条验证后补齐的三个缺口。**不在原路线图里** —— 是拿真需求比对代码才浮出来的。
