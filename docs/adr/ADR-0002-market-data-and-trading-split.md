# ADR-0002 期货行情走 Quote API，交易走 CTP（通道分离）

- 日期: 2026-08-28
- 状态: Accepted

## 背景
用户已有 Quote API（`<自有行情服务，地址配在 .env 的 QUOTE_API_BASE>`）提供国内期货/股票/外盘 K 线；实盘下单需要 CTP。
两者代码体系、时间语义、可用时段均不同。

## 决策
1. **期货行情**：Quote API，HTTP 轮询（该接口无推送能力）。每根 bar 收盘后 +1.5s 拉取，
   带重叠窗口做缺口校验。
2. **期货交易**：CTP（openctp / vnpy 网关），仅在 M5 引入。
3. **加密**：行情与交易均走交易所（WS + ccxt）—— 实测 Quote API 无加密数据。
4. **`SymbolRegistry` 为唯一映射源**：内部 symbol ↔ QuoteAPI code ↔ CTP code ↔ 交易所 code。
   交易模块启动时校验三方映射完整，缺失则拒绝启动。

## 权衡
- 优点：行情侧不受交易账户/开盘时段限制，历史数据一次批量拉取（支持 2000 品种/请求），回测数据准备极快。
- 代价：**多一层代码映射，是下错单的头号风险来源** ⇒ 用启动期强校验 + 纸上撮合先行来兜底。
- 代价：轮询有 1~2s 延迟，且无 tick/盘口 ⇒ 本系统定位分钟级，可接受；若将来需要盘口，再单独接 CTP 行情。

## 已知限制与实测问题
- `GET /api/v1/varieties/main` 当前返回 500（服务端故障），主力映射改用 `POST /main-by-date`。
- 分钟线与日线的 `time_stamp` 语义不一致（前者为收盘 epoch，后者为交易日 UTC 零点），
  必须分路径转换。
- **TLS 为自签名证书**。官方示例建议 `verify=False`，这会关闭 MITM 防护，而请求头里带着 AK。
  本项目做法：首次连接抓取证书指纹存入 `QUOTE_API_TLS_FINGERPRINT`，之后**固定指纹校验**
  （自定义 SSLContext + 指纹比对），而非全局关闭校验。
- AK 只存 `.env`（已 chmod 600 + gitignore），不进代码、不进日志、不进文档。
