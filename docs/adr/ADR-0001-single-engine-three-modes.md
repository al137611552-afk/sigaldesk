# ADR-0001 单引擎三模式：回测/预警/交易共用信号代码

- 日期: 2026-08-28
- 状态: Accepted

## 背景
盯盘预警、策略回测、自动交易若各写一套信号判定，行为必然漂移：回测赚钱、实盘不触发，且无从排查。

## 决策
只实现一套 指标→形态→规则 的求值链路。三种模式的差异全部收敛到两端：
- 入口 `Feed`：LiveFeed(轮询/WS) vs ReplayFeed(Parquet)
- 出口 `Sink`：Notifier vs SignalStore vs Broker

求值层通过 `BarStore.view(symbol, as_of)` 取数，该视图物理截断 `close_ts > as_of` 的数据。

## 备选与权衡
- **A. 回测与实时各写一套**：短期快，长期必然不一致。否决。
- **B. 直接用 vnpy/backtrader 的策略基类**：绑定其数据模型与多周期处理方式，
  而多周期对齐正是本项目最核心的自研点，框架内改造成本高于自研。否决（其 CTP 网关仍可单独复用）。
- **C. 单引擎 + as-of 视图**（选定）：多写一层视图抽象，换来结构性的正确保证。

## 已知限制
- as-of 视图对每次求值有轻微开销（切片/索引），分钟级场景可忽略。
- 强约束会让某些"需要全局信息"的形态写起来别扭 —— 这恰是想要的（那类形态本身就有前视偏差）。

## 验收
M2 的一致性校验：同一时段 replay 与 live 产出的信号逐条一致（数量、时间戳、触发价）。不一致即视为 bug。
