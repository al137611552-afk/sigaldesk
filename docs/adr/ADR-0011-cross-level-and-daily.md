# ADR-0011 跨级别引用与日线聚合

- 日期: 2026-08-31
- 状态: Accepted

## 背景

用户的实际打法是"看大做小"：大级别定方向、小级别找买点（价格贴近小时/日线均线附近）、
分钟双底或 5m 金叉后走出箱体，然后预警。把这套写成规则时暴露了三个缺口：

1. **双底写不出来**。`swing_low(5)` 返回的 `Level` 内部一直带着 `prev`（`cross_up` 就在用），
   但表达式层从未暴露它，算术语境下只会降解成 `cur`。
2. **日线用不了**。`Timeframe.D1.seconds == 0`，`BarStore` 只做墙钟分桶，
   加载器直接拒绝 `on: 1d`。
3. **跨级别引用写不出来**。一个条件只能看自己那个周期的数据，
   "5m 那一刻价格距 1h 均线多远"表达不了，只能近似成"1h 收盘时贴近" ——
   实测这个近似不是无害的：同一策略两种写法在 3 个月 rb 数据上是 41 条 vs 37 条信号。

## 决策

### 1. 跨级别用**一个特殊形式** `at('1h', <表达式>)`，不给每个指标加周期参数

备选是给 `sma/ema/atr/rsi/macd_*/kdj_*/boll_*/highest/lowest/swing_*/consolidation/...`
每个都加一个可选 `tf` 参数。否决理由：三十多处签名改动、每加一个新原语都要记得再加一次、
而且 `at('1h', a and b)` 这种"整段换级别"表达不出来。

`at` 是求值器里的**特殊形式**：第二个参数不先求值再传入，而是在**切换后的上下文**里求值。
一处改动解锁全部现有与将来的指标、形态原语。

### 2. as-of 由**外层视图定死**，跨级别不会偷看未来

`at()` 复用同一个 `BarView`，截断位置完全一致。5m 那根收在 10:05 时，
1h 侧看到的是 10:00 收盘那根 —— 最近一根**已收盘**的 1h，不是正在走的那根。
这既满足 INV-1/INV-2，也正是"大级别定方向"该有的语义。

指标缓存仍按 `(symbol, timeframe)` 分开：1h 的 EMA 只算一份，
不管是被 1h 的条件用还是被 5m 的条件通过 `at()` 用。

### 3. `at()` 的周期必须是**字面量**，且规则要自报需要哪些周期

`Rule.required_timeframes` 汇总"条件自身的周期 ∪ `at()` 引用的周期"，
`store_timeframes(rules)` 是建 `BarStore` 的唯一入口。

**为什么非这样不可**：少派生一个周期的后果不是报错，而是该级别恒为空序列 →
指标恒 `None` → 条件恒"不成立" —— 一条信号都不报，且毫无提示。这是最难查的一类失败。
所以周期必须编译期可知（不接受变量），并且 `_ViewSource.bars_at` 在取不到时**当场抛错**。

### 4. 日线按**交易日**聚合，独立于墙钟分桶

`DayBuilder` 与 `BarBuilder` 并列而不是复用：高周期靠 `ceil(close_ts/period)` 算桶边界，
落在边界上的那根当场收盘；日线的边界由交易日归属决定，而交易日长度不固定
（有无夜盘、节假日前后都不同）。

- 分桶键 = `trading_day`（期货），无则退回 UTC 自然日（加密），与 Parquet 分区键同口径。
- **夜盘归属下一交易日**：08-27 21:00 那根属于 08-28，与当日日盘合成同一根日线。
  按自然日切会把每个交易日劈成两半，且不会报任何错。
- 只能在**日期键变化时**收盘，比真实收盘晚一根 bar。实际影响很小：期货的下一根是
  21:00 夜盘（已属下一交易日），所以上一日的日线在下一交易日一开盘就可用；
  空窗只落在 15:00 收盘到 21:00 开盘之间，那段时间本来就没有行情。
- **当日未走完的日线永远不吐出**（INV-2）。

`Timeframe.rank` 专门用于排序：`D1.seconds` 是 0，按 `seconds` 排会把日线排到 1m 前面。

### 5. 函数调用形状在**编译期**核对

`FuncSpec` 带上 `inspect.signature`，编译期用 `bind` 核对参数个数与名字。
起因是实测发现 `ema(close, 60, '1h')` 能编译通过，要等**上线后第一根 bar** 才抛
`TypeError` —— 而 `config/rules/` 是 fail-fast 加载的，坏规则本不该进得了生产。
同时拒绝 `f(**d)`：它的 `keyword.arg` 是 `None`，求值器会静默丢掉，参数凭空消失。

## 后果

- 能写"5m 那一刻价格距 1h/1d 均线多远"，不必再用"大级别收盘时判"去近似。
- 日线可作为条件级别，也可被 `at('1d', ...)` 引用。
- `prev(x)` 暴露了本来就存在的"上一根"；`double_bottom/double_top` 是它的语法糖，
  额外做了**颈线检查** —— 没有颈线的两个相近低点不是双底，是横盘。
- 手写 `DERIVED` 常量的地方都改成 `store_timeframes(rules)` ∪ 默认档。
- 代价：`at()` 让表达式可以任意深地嵌套周期切换（`at('1h', at('5m', ...))` 合法但无意义）。
  暂不禁止，因为它不会产生错误结果，只是没用。
